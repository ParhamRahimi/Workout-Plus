# Security

Do not post vulnerabilities or real fitness data in public issues. Use GitHub
private vulnerability reporting when available. Maintainers must enable that
feature before a public release and supply a private fallback contact if needed.

Reports should describe the affected version, a reproduction using synthetic
data, and expected impact. Do not include credentials, progress photos, personal
backups, device identifiers, or unrelated private files.

Only the current release will receive security fixes initially. Keep the
repository private until the history/asset audit and release checklist pass.
